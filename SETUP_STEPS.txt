===============================================================================
NETRA - SETUP AND RUN STEPS (Windows / PowerShell)
Owner E (M11 dashboard) + Owner D (M6/M7 server)
===============================================================================

Read this once before starting. Steps 1-5 are one-time setup. Step 6 is what
you run every time afterwards.

Use  py -3.14  everywhere, NOT  python3 .
The msys2 python3 on this machine has no CA certificate bundle, so any script
that touches the internet will fail with CERTIFICATE_VERIFY_FAILED.

Use  curl.exe , NOT  curl .
In PowerShell, plain "curl" is an alias for Invoke-WebRequest, which prints a
script-execution warning and dumps a giant object instead of the JSON body.


===============================================================================
STEP 1 - UNZIP
===============================================================================

Unzip netra-merged.zip so you end up with a folder named  netra  containing:

    netra\
      contracts\      web\        server\     tools\
      fixtures\       edge\       eval\       demo\

If your unzipper nested it (netra\netra\...), move the inner folder up a level.

Open PowerShell and cd into it:

    cd "C:\My Programs\Hackathons\Nethra-SIH\netra"

Everything below assumes you are in that folder unless it says otherwise.


===============================================================================
STEP 2 - ADD YOUR CARTO BASEMAP KEY
===============================================================================

Open this file in a text editor:

    web\js\config.js

Find the "carto" block and set the key:

    carto: {
      key: "cb1_2jia_1_93e45b0074f70164ae508e69",
      style: "dark_all",
    },

NOTE: this is the CARTO *Basemaps* key (from carto.com/basemaps/apikey).
It is NOT the CARTO Platform API token from the CARTO workspace - that one
authenticates carto_dw data sources and will not serve basemap tiles.

Without a key the map still works, tiles are just watermarked.


===============================================================================
STEP 3 - POSTGRES DATABASE (one time)
===============================================================================

You already installed PostgreSQL 18. Create the database and user:

    & "C:\Program Files\PostgreSQL\18\bin\psql.exe" -U postgres -c "CREATE USER netra_user WITH PASSWORD 'netra_pass';"
    & "C:\Program Files\PostgreSQL\18\bin\psql.exe" -U postgres -c "CREATE DATABASE netra OWNER netra_user;"

It will prompt for the postgres superuser password you set during install.

Verify (password is netra_pass):

    & "C:\Program Files\PostgreSQL\18\bin\psql.exe" -U netra_user -d netra -c "SELECT current_database();"

Should print:  netra

PostGIS is NOT needed. The server tries to enable it, logs a warning if it is
missing, and carries on with plain Postgres. That is a tested path.

OPTIONAL - add psql to PATH for this terminal session only:

    $env:Path += ";C:\Program Files\PostgreSQL\18\bin"


===============================================================================
STEP 4 - (REMOVED) FETCH ROAD GEOMETRY
===============================================================================

No longer needed. The dashboard no longer draws road corridors, so there is
no OpenStreetMap fetch and no fixtures/road_network.json dependency. The map
shows one severity pin per uploaded site instead.

tools/fetch_roads.py, fixtures/road_network.json and web/js/roads.js are still
in the tree, unreferenced, if the corridor view is ever wanted back.

If you want the bundled offline fixtures refreshed:

    py -3.14 tools/gen_fixtures.py
    py -3.14 tools/build_standalone.py


===============================================================================
STEP 5 - INSTALL SERVER DEPENDENCIES (one time)
===============================================================================

    cd server\api
    py -3.14 -m pip install -r requirements.txt
    cd ..\..

Video upload runs ingest_video.py, which needs the detector and norms extras:

    py -3.14 -m pip install -r requirements.txt

(scikit-learn and matplotlib are in there now - edge/norms imports both at
module level, so an upload cannot start without them.)


===============================================================================
STEP 6 - RUNNING IT (every time)
===============================================================================

You need TWO terminals, both in the netra folder.

--- TERMINAL A: the API server (owner D) ---

    cd server\api
    py -3.14 -m uvicorn netra_server:app --port 8000

Watch the startup log. You want to see:

    PostgreSQL initialized

This is fine and expected:

    PostGIS unavailable, using plain Postgres

Leave this terminal running.

--- TERMINAL B: the dashboard (owner E) ---

Run this from the REPO ROOT, not from inside web\ :

    py -3.14 -m http.server 8080

Then open in your browser:

    http://localhost:8080/web/

Hard-refresh with Ctrl+Shift+R the first time - map tiles cache aggressively.


===============================================================================
STEP 6b - ADD A VIDEO (the main flow now)
===============================================================================

In the dashboard, top right:  + Add video

  1. Choose a clip (mp4 / avi / mkv / mov / webm, up to 2 GB).
  2. Give the site a name.
  3. Set the location: type lat/lon, click "Use map centre", or click
     "Pick on map" and then click the spot. Escape cancels picking.
  4. Choose the processing depth:

         Quick      600 frames    yolov8n.pt   - for a live demo
         Standard   2,400 frames  yolov8m.pt   - the default
         Full       whole clip    yolov8m.pt

  5. Upload and analyse.

Each upload adds exactly ONE pin, at the coordinate you gave it. Nothing
else puts a pin on the map - the database starts empty and sample events are
no longer auto-seeded.

A blue pin with a spinner appears at once. The dashboard polls every 3
seconds; the pin turns red (severe), amber (conflict) or green (no conflicts
above threshold) when the run finishes, and the event list, charts and
narratives fill in. Click the pin for that site's hourly pattern, speed
distribution and the annotated render of its clip.

The processing depth is a FRAME BUDGET, not a quality setting. Never quote a
recall or false-positive figure from a Quick run.

WHAT THE PIN MEANS - say this before a judge asks. The coordinate is the one
you typed. An uploaded clip has no calibration, so the pipeline builds a
generic road plane and the location on its events is a placeholder; the server
replaces it with yours. Distances, speeds, TTC and PET are the pipeline's
measured metric output. The pin is a site marker, not a GPS fix on the
vehicles.

Uploads are listed at the bottom of the Add video panel with their status and
event counts, and "Remove" deletes a clip along with the events it produced.


===============================================================================
STEP 7 - SEED TEST DATA
===============================================================================

The database starts empty, so the map will be live but blank. Fill it:

    py -3.14 tools/seed_events.py --count 40

Options:
    --count 60          how many events
    --seed 12           different random layout (same seed = same events)
    --dry-run           print the events instead of posting them
    --api http://...    if the server is not on localhost:8000

WARNING: this is synthetic test data, NOT detector output. Never present it
as a measured result. Clear it before showing any accuracy figures (M9):

    & "C:\Program Files\PostgreSQL\18\bin\psql.exe" -U netra_user -d netra -c "DELETE FROM events WHERE event_id LIKE 'evt_seed_%';"


===============================================================================
STEP 8 - VERIFY IT ALL WORKS
===============================================================================

In a third terminal:

    curl.exe http://localhost:8000/api/health
    curl.exe http://localhost:8000/api/events
    curl.exe http://localhost:8000/api/segments

What to look for:

  health    ->  "postgres":true
  events    ->  "ok":true  and  "location":[12.87009,74.86409]
                (NOT ["7","("] - that was a bug, now fixed)
                and "conditions" populated with light/weather/hour_of_day
  segments  ->  "ok":true  with several clusters
                (NOT an st_y error - that was a bug, now fixed)

In the browser at http://localhost:8080/web/ :

  [ ] Badge top-right reads "Live API connected"
  [ ] Basemap streets visible in dark grey (CARTO)
  [ ] A severity pin at every uploaded site
  [ ] Right panel shows the overview + "Sites by risk"
  [ ] Clicking a pin shows hourly chart + speed histogram + annotated clip
  [ ] Clicking "Rain" filter changes the event count
  [ ] Clicking "After dark" changes it again
  [ ] Clicking an event row opens narrative + clip

The two filter checks matter most - that is PRD success criterion S5.


===============================================================================
BADGE MEANINGS (top right of the dashboard)
===============================================================================

  "Live API connected"        Everything working.

  "API up, database down"     Server is running but cannot reach Postgres.
                              Go back to STEP 3. Check Postgres is running
                              on port 5432.

  "Offline - showing fixtures"  Cannot reach the server at all.
                              Check Terminal A is still running, and that
                              apiBase in web\js\config.js says
                              http://localhost:8000


===============================================================================
TROUBLESHOOTING
===============================================================================

curl POST gives "JSON decode error"
    PowerShell mangled the quoting. Use tools/seed_events.py instead.

Map has no pins
    Expected on a fresh start - the database begins empty and pins come only
    from uploads. Use + Add video.

    tools/seed_events.py (STEP 7) adds test EVENTS, which fill the event list
    and charts but deliberately produce no pins: they have no clip and no
    operator-entered location behind them.

Upload fails with "Could not reach the server"
    Terminal A is not running, or apiBase in web\js\config.js does not match
    the port uvicorn is on.

Clip plays as a black box / "MIME type not supported" / format error
    The annotated render is MPEG-4 Part 2 (mp4v) - what OpenCV writes, and
    what no browser decodes. The server re-encodes it to H.264 after each
    run, but only if it can find ffmpeg. Fix:

        py -3.14 -m pip install imageio-ffmpeg

    then re-upload the clip. Already-processed clips keep the old encoding
    until they are run again. The job's message says when the step was
    skipped, and the player shows a link to open the file directly (it plays
    fine in VLC).

An upload goes straight to "error"
    Open data\videos\<job_id>\pipeline.log - it holds the full pipeline
    output. A missing module there means STEP 5 was skipped.

Map tiles missing but pins show
    No internet, or the CARTO key is wrong. Not fatal - the risk layer is
    independent of the basemap, which is deliberate (PRD S6: the demo must
    survive with the network unplugged).

Watermark on the map tiles
    CARTO key missing or not picked up. Check STEP 2, re-run
    build_standalone.py if using the standalone file, hard-refresh.

Port 8080 already in use
    Something else grabbed it (older pgAdmin does this). Use another port:
        py -3.14 -m http.server 8081
    then open http://localhost:8081/web/

Postgres authentication failed
    PG18 defaults to scram-sha-256. psycopg2 handles it. If it still fails,
    check pg_hba.conf uses scram-sha-256 for local connections.


===============================================================================
CHANGING THE OPENING MAP VIEW
===============================================================================

web\js\config.js -> junction.center and junction.name set where the map opens
before anything has been uploaded. That is all they do now. Every real site
comes from the location entered with a video, so nothing else has to change
when the demo site is decided.

ALSO: server\api\netra_server.py has WeatherEnricher defaulting to
13.0106, 74.7943. It only shifts sunrise/sunset by seconds, but it should
track the real site.

===============================================================================
WHAT IS NOT DONE YET
===============================================================================

Built:      M11 dashboard (E), M6/M7 server (D)
Not built:  M1-M5, M8-M10 - placeholder READMEs only

Known gaps worth raising with the team:

  1. PRD Section 5.5 lists API routes but not response bodies. That gap
     caused most of the integration bugs. The verified shapes are written
     up in contracts\http_api.md - propose adopting that as the real
     frozen contract. The four /api/videos routes are documented in
     server\PATCHES_TO_OWNER_D.md and want the same treatment.

  2. /api/segments returns scored POINTS, not road geometry. That no longer
     blocks anything - the map is pin-based - but the endpoint is now only a
     cross-check and the PRD still implies it drives the map.

  3. Clip playback (M11 P0) now has a path: an uploaded clip's annotated
     render is served from /videos/<job_id>/out/annotated_video.mp4 and the
     event's `clip` field points at it. Section 5 still says nothing about
     how a clip reaches the frontend; this is the de-facto answer and should
     be written into the contract.

  4. compute_risk_score() in netra_server.py implements the PRD's
     risk = base x rain x night x peak model, but NOTHING CALLS IT. So the
     condition-multiplier design - one of the five defensible claims - is
     not actually running. Worth fixing before anyone demos it as working.

  5. An uploaded clip has no calibration, so ingest_video.py builds a generic
     road plane. Metres and km/h from such a run are NOT calibrated to that
     site. The measured 0.136 m rms figure belongs to the demo clip's own
     calibration and must not be quoted for an uploaded one.

10 bugs were found and fixed in D's server. See server\PATCHES_TO_OWNER_D.md
for the full list with severity and cause - 5 were hard blockers, and 4 were
only visible by running the code against a real Postgres, not by reading it.
